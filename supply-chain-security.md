# Supply Chain Security

This document describes the supply-chain security posture of the Crypto Broker
project, the [SLSA](https://slsa.dev/) build level we target, and how consumers can independently verify released artifacts.

## Target SLSA build level

The Crypto Broker targets **SLSA Build Level 3** for its released container images and binaries.

Provenance is generated by centrally-managed **reusable workflows** in the [`open-crypto-broker/.github`](https://github.com/open-crypto-broker/.github) repository, executed on ephemeral GitHub-hosted runners, and signed with a short-lived [Sigstore](https://www.sigstore.dev/) certificate (Fulcio + Rekor) via [GitHub artifact attestations](https://docs.github.com/en/actions/security-guides/using-artifact-attestations-to-establish-provenance-for-builds).
Because provenance is produced and signed by a reusable workflow rather than inline in each project, the signer identity is non-forgeable and centrally enforced — the distinguishing requirement of Build Level 3 over Level 2.
Consumers can assert that a specific trusted workflow signed an artifact via the `--signer-workflow` flag during verification (see [Verifying a release](#verifying-a-release)).

This follows GitHub's documented approach for reaching [SLSA v1.0 Build Level 3 with artifact attestations and reusable workflows](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/increase-security-rating).

### How Build Level 3 is met

| Requirement | How it is satisfied |
| --- | --- |
| Provenance exists and is available | Build + SBOM attestations for every image and binary, stored in the GitHub attestations API. |
| Managed, ephemeral build platform | Builds run on GitHub-hosted runners, provisioned fresh per run. |
| Signing isolated from user-defined steps | Signing uses GitHub-managed OIDC + Sigstore; no key material is exposed to build steps. |
| Provenance signed by a reusable workflow | Binaries are signed by `build-release.yaml` and container images by `release-docker-security.yaml`, both reusable workflows in `open-crypto-broker/.github`. |

## What is provided per release

- **Signed build provenance** for container images (GHCR) and release binaries.
- **Signed SBOM attestations** (SPDX) for container images and binaries; SBOMs are also published as GitHub Release assets.
- **Vulnerability scanning** (Grype) gated at `critical` severity on release.
- **Pinned dependencies**: all external GitHub Actions are pinned to full commit SHAs; internal reusable workflows/actions are pinned to a commit SHA and kept current automatically by Dependabot.
- **Least-privilege** workflow permissions, with workflows statically analysed by `actionlint` and `zizmor` in CI.

## Where to find artifacts and attestations

- **Container images**: `ghcr.io/open-crypto-broker/<image>`.
- **Binaries and SBOMs**: GitHub Release assets of the respective component repository.
- **Attestations**: stored in the GitHub attestations API and, for container images, also attached to the container image as OCI referrers.

## Verifying a release

Verification uses the GitHub CLI.
Provenance and SBOM attestations are checked with [`gh attestation verify`](https://cli.github.com/manual/gh_attestation_verify).

Prerequisites:

- GitHub CLI (`gh`) 2.x or newer.
- For images: `docker login ghcr.io`.

Replace `<repo>`, `<image>`, `<digest>`, `<name>`, `<tag>` and `<platform>` with the values for the release you are verifying.

### Container image

Verify build provenance, asserting the trusted reusable workflow signed it:

```bash
docker login ghcr.io
gh attestation verify oci://ghcr.io/open-crypto-broker/<image>@<digest> \
  -R open-crypto-broker/<repo> \
  --signer-workflow open-crypto-broker/.github/.github/workflows/release-docker-security.yaml
```

Verify the SBOM attestation:

```bash
gh attestation verify oci://ghcr.io/open-crypto-broker/<image>@<digest> \
  -R open-crypto-broker/<repo> \
  --signer-workflow open-crypto-broker/.github/.github/workflows/release-docker-security.yaml \
  --predicate-type https://spdx.dev/Document/v2.3
```

### Binary

Download the release archive (and its `.spdx.json` SBOM) from the GitHub Release, then verify build provenance, asserting the trusted reusable workflow signed it:

```bash
gh attestation verify <name>-<tag>-<platform>.zip \
  -R open-crypto-broker/<repo> \
  --signer-workflow open-crypto-broker/.github/.github/workflows/build-release.yaml
```

Verify the SBOM attestation:

```bash
gh attestation verify <name>-<tag>-<platform>.zip \
  -R open-crypto-broker/<repo> \
  --signer-workflow open-crypto-broker/.github/.github/workflows/build-release.yaml \
  --predicate-type https://spdx.dev/Document/v2.3
```

A successful verification confirms that the artifact was built by the named repository's GitHub Actions workflow from the claimed commit and has not been modified since.
